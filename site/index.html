For rented H100, H200 and A100 GPUs

Skip the GPU test when someone already did it.

A full GPU test takes 60 to 90 minutes. dud checks a rented GPU against a shared registry in approximately 1 minute.

If another renter tested the GPU recently and it passed, start your work. If the GPU has a KILL verdict, dud warns you before you lose time on it.

  1. Get access one time

    Run dud full on one GPU. An accepted full test gives 30 days of registry access.

  2. Check each new GPU

    On each GPU that you rent, run dud quick. It takes approximately 1 minute.

  3. Decide in 1 minute

    A recent KEEP: start your work. A KILL: ask the provider for a different GPU.

  4. No record yet?

    Run dud full. Your result helps the next renter of that GPU.

The card record

Every GPU gets a history, like a used car

Each full test adds a reading to the record of that GPU. The record stays with the GPU when it moves to a different provider.

GPUs of the same model are not equal. Some have used many of their spare memory rows. The provider does not tell you this. The GPU does.

Two tests

A short look, or the full examination

dud quick · approximately 1 minute

Quick test

  • Reads the identity and the history of each GPU on the node.
  • Compares the GPU with its earlier registry readings, if you have registry access.
  • Sends only card IDs to the registry.
  • Writes a result file and a report on the node.
dud full · approximately 60 to 90 minutes

Full test

  • Does everything that the quick test does.
  • Does the registry challenge, which proves that a real GPU did the work.
  • Adds the DCGM test, performance tests and a load test in a later version.
  • Sends the result to the registry. An accepted full test gives 30 days of registry access.

dud tests each GPU on its own, and reports on the node as a whole. A node can have 1 to 8 GPUs.

What dud reads

The GPU keeps its own records

Each GPU records its memory errors and memory repairs. These records stay with the card when it moves from one provider to the next.

Identity

  • Model and form factor (SXM, PCIe or NVL)
  • Card ID and serial ID (hashes)
  • VBIOS, driver and CUDA versions
  • Total memory, default and current power limit
  • PCIe link generation and width, NVLink, GPU connections

History

  • Correctable and uncorrectable ECC errors, volatile and aggregate counts
  • Row remaps: correctable, uncorrectable, pending and failed
  • Bank availability: how many memory banks still have spare rows
  • Retired pages, on older GPUs
  • XID errors in the kernel log

Visibility

For each value, dud records a status:

available blocked not supported error

An H100 always records ECC errors. If nvidia-smi shows N/A, the provider, the VM or the container blocks the value. A blocked value is a finding about the provider.

dud keeps the raw output of each command, for example the full nvidia-smi -q -x XML. The registry uses it to check each value.

The registry

Anyone can test. Only testers can look up.

Anyone can run dud. To read the registry, you need an accepted full test from the last 30 days. Without access, no registry data is available: not for one card and not as totals.

30daysof registry access after each accepted full test
100lookupsfor each account each day
1card IDin each lookup. There is no list of cards and no export.
10%maximum weight of one contributor in the stats for a model

Stats for a model show percentiles only. They need 20 or more cards from 10 or more contributors. New contributors start with low trust. Their trust goes up when their readings agree with other readings of the same cards.

Fraud

The registry trusts no client

dud is open source, so anyone can change the client. All checks run in the registry. This is the sequence for each full test:

  1. A single-use nonce

    The registry gives a nonce for each full test. The nonce expires after 3 hours.

  2. Work that nobody can do before

    Each GPU does matrix work on its tensor cores. The nonce and the card ID set the input values.

  3. A commit and a clock

    The client sends one Merkle root of all results. The registry clock measures the time. Too fast or too slow for the model: rejected.

  4. Spot checks

    The registry picks results at random and checks each one exactly.

  5. The raw output, read again

    The registry reads the raw nvidia-smi output with its own parser. Each value must agree. Memory and power must agree with the datasheet. Aggregate counts must not go down.

Nobody can make fraud impossible. The goal is that fraud costs more than an honest test, and that an admin can find it. THREATS.md lists each threat, its defense and the remaining gap.

Privacy

What leaves your node

  • The GPU UUID and serial number never leave the node. dud replaces them with SHA-256 hashes before it writes or sends a file.
  • dud removes process names and process IDs from the raw output.
  • From the kernel log, dud keeps only XID error lines.
  • The quick test sends only card IDs. The full test sends the result file.
  • The registry stores each card ID as a keyed hash, not as the card ID.
Card ID

On the node, run nvidia-smi --query-gpu=uuid --format=csv,noheader. Paste one UUID here. Your browser calculates the card ID. The UUID does not leave this page.

Install

Run dud on a rented node

dud needs Python 3.9 or later and the NVIDIA driver. The full test also needs PyTorch with CUDA. If PyTorch is not installed, dud asks before it installs it.

The package name is dud-gpu. The command is dud. dud is not on PyPI yet. Until then, build it from the source code.

pip install dud-gpu
